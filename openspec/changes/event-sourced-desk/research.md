## Что в посте стоит уточнить

Отказ от OpenSpec и Event Sourcing решают разные проблемы. ES задает способ принимать решения
и хранить состояние; OpenSpec задает организацию изменений. Исполняемый контракт может жить
внутри OpenSpec, что уже делает Desk. Удаление Markdown само по себе не создает ни ES, ни
устойчивость к рефакторингу.

Утверждение о хорошей работе coding agents со спецификациями - опыт автора. В модуле нет
сравнительного эксперимента на Desk или гарантии качества агентов. Принимаем проверяемые
принципы, а эффект оцениваем по сохранению поведения, понятности расхождений и возможности
заменять реализацию без изменения договоренностей.

Часть материала использует исторические примеры .NET, ProtoBuf, Lokad и старые библиотеки.
Для Desk переносим модель, а не эти зависимости. Наша связка TypeScript, Hono и YAML допустима.
Full-stack HTTP observations и браузерные проверки остаются расширением применения метода;
обязательного перехода на серверный рендеринг в модуле нет.

## Что уже есть в реализации

| Область | Найдено в коде | Что меняем |
| --- | --- | --- |
| Контракты | `server/desk-dsl.ts`: один When, cases, response bindings, публичные GET observations, канонический hash. | Сохраняем язык и id; расширяем смысл event assertions только при переносе области. |
| Согласования | `server/review-store.ts`: восемь типов событий, import checkpoint, replay approvals. Новые события выводятся сравнением previous/next ReviewDoc. | Решение команды должно выдавать события до записи проекции. |
| Хранение review | `readReview` сначала читает и валидирует YAML, затем воспроизводит approvals. Поврежденный YAML сейчас мешает чтению, даже если журнал согласований цел. | Разделяем авторитетные данные и производную проекцию по областям; не обещаем восстановление еще не перенесенных полей. |
| Конкурентность | `withReviewLock` сериализует операции в одном процессе. История целиком заменяется через временный файл и rename. | Сохраняем сериализацию, добавляем проверку версии и явное ограничение единственного writer; не выдаем файловый append за транзакционную БД. |
| Бизнес-правила | `server/routes/review.ts`, `server/readiness.ts`, `server/routes/threads.ts`, `server/decision-model.ts`, `server/decisions-md.ts`. | Переносим правила вместе с конкретным workflow; routes оставляют transport и вызов application command. |
| Инициативы | `server/initiative-store.ts`: `initiative.yaml` для плана, inputs и runs. Решения инициативы живут в отдельном `review.yaml`; `server/initiative-decisions.ts` координирует оба. | Рассматриваем согласование плана и разрешения research как одну границу согласованности инициативы. |
| Агенты и эффекты | `server/questions.ts`, `server/run-service.ts`, `server/apply.ts`: изменения snapshots, процессы, логи и уведомления. | Отделяем устойчивое намерение и результат от запуска CLI, Docker и Git. |
| EventBus | `server/events.ts`: неперсистентные notifications для UI/SSE. | Оставляем транспортом обновлений; потеря уведомления не должна терять доменный факт. |
| Usage | `server/agent-usage.ts`: отдельный журнал started/completed и сводная проекция. | Сохраняем специализированный учет, связываем его с execution id. Переносить токены и дельты в review stream не нужно. |
| Исполнение specs | `scripts/run-desk-specs.mts`, `server/testing/desk-world.ts`: реальный HTTP и disk-backed storage; scripted transport для моделей. Часть Given создает состояние через setup-команды. | По мере переноса Given подает историю через production decoder/projector в disposable repo, без скрытой коллекции проверок в адаптере. |
| События в specs | `DeskWorld.events()` читает только approval journal. Поэтому `events: []` у обсуждений и решений сейчас не означает отсутствие событий во всем домене. | Меняем границу наблюдения только отдельной явно согласованной версией контракта или режима исполнения. |
| OpenSpec | `server/discovery.ts`, `server/room.ts`, `server/vet-output.ts`, `server/author-run.ts`, `server/apply.ts`. | Сначала общий интерфейс пакета изменения, затем native Desk package и legacy adapter. |
| Связь сценариев | Approval key DSL - `file::id`; `server/joinkey.ts` связывает Markdown по title, `server/corpus.ts` и run messages также используют title. | Нельзя просто удалить spec.md: нужно перенести comparison и results на stable id с совместимостью старых ключей. |

В рабочем дереве до исследования уже были незакоммиченные изменения конфигурации, UI и
документации, а также `independent-workspaces`. Этот план их не изменяет и не включает в миграцию.

## Исходная проверка

На текущем рабочем дереве `npm test` выполнил 51 сценарное исполнение успешно, technical Vitest
suite пуст и завершился успешно. `npm run typecheck` прошел. `npm run e2e` завершился с
13 успешными browser checks. `npm run test:self` подтвердил 38 corpus contracts, 51 исполнение
и 37 совпадающих контрактов self-review через authenticated local runner.

Это подтверждает исходную точку, а не проверяет еще не написанную реализацию миграции.
Старые тексты о 37 правилах / 50 исполнениях уже не полностью описывают corpus: есть
дополнительный контракт usage. Новых тестов и контрактов в ходе исследования не добавлялось.
